# 一本指で歩く「凪の島」の操作設計

## 根拠と採用した操作

- [Unity公式のオンスクリーン入力](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.13/manual/OnScreen.html) は、指を置いた位置を基準にスティック量を取り、指を離したら入力を止める構成を説明している。この起点・移動量・解除の基本を使う。操作ロジックに見た目は必須ではないため、島には操作用の表示を足さない。
- [Roblox公式のカメラ操作](https://create.roblox.com/docs/reference/engine/enums/CameraMode) は、モバイルでのドラッグによる視線操作を説明している。ただし本作は「基本は一本指」を優先するため、移動とカメラを別の指で操作させず、一本の入力で前後移動と水平旋回を同時に指定する。
- 以前の「短い横入力は横歩き、大きい横入力は旋回」という補間は廃止する。横入力の意味は常に旋回。指の移動量に応じて曲がる速さだけを変える。

これらは共通する入力の仕組みからの設計判断であり、すべてのスマホ3Dゲームに同じ操作があるという意味ではない。

## 調整値

| 項目 | 以前 | 今回 |
| --- | --- | --- |
| 前進の最高速度 | 6.4 | 7.8（約22%増） |
| 後退の最高速度 | 3.6 | 5.4 |
| 横スライド | 横歩きから旋回へ切替 | 常に水平旋回 |
| 斜めの指入力 | 前進と横歩きの合成 | 前進量を保って旋回 |
| 視野角 | 62度 | 68度 |
| 挨拶の開始距離 | 3.5 | 4.8 |

水平旋回の微小入力は穏やかにし、大きな入力では十分に曲がれるようにした。加速は短く、指を離す・原点へ戻す操作は即停止する。移動速度は向いている方向へ回るので、方向を変えたあと古い向きへ滑る慣性を残さない。歩行時の頭の揺れや上下視点は加えない。足音は移動した距離で数え、旋回だけ・衝突で進めない状態では鳴らさない。

## 検証するユースケース

1. 下半分のどこに指を置いても、触れただけでは動かない。
2. 上に倒せば直進し、横へ少し・大きく動かしても常に旋回になる。
3. 一本指を斜めに倒すと、前進量を保って曲がれる。
4. 下へ倒した後退でも、左右へ倒さない限り向きは変わらない。
5. 指を原点へ戻す・離す・中断する・画面を切り替えると移動と旋回が止まる。
6. 小さなスライドは、島民の近くでの位置調整に使える。
7. 画面端付近の起点でも急に別の動作へ切り替わらない。
8. 海際に押しつけたままでも海へ抜けず、足音も増えない。反対へ倒せば戻れる。
9. 2本指の誤操作、長押し、回転・復帰の後に入力が残らない。
10. 挨拶が新しい距離で始まり、実際の投影行列が68度の画角になっている。
11. 開始直後から全速で走っても、最初の島民の挨拶を待ち時間の間に通り過ぎない。

ブラウザ検証は実タッチイベントで実施する。iPhone実機での感触は別途確認が必要。

## 北側拡張時の追加調整

起点と画面端の間隔でスライド感度を変える処理を廃止。画面サイズに応じた64〜96 CSS pxの操作幅を使い、同じ画面では置く位置によって感度が変わらないようにした。基本の遊び幅は9 px、前後入力が最大のときの横方向は13 pxとして、直進時の指ぶれを吸収する。横入力の意味は常に旋回のまま。

操作幅をさらに16 px以上越えるスワイプでは、越えた分だけ起点を追従させる。長く滑らせた距離を全部戻さなくても切り返せる。指を離すと次回の起点は新しく取り直す。

移動時はX→Zの順でそれぞれ止める方式から、まず全方向の移動を試して、衝突時は接触面の接線へ投影する方式に変更。丸い幹・岩と海岸で、特定のワールド軸へ吸い寄せられる動きを減らした。足音は引き続き実際に移動した距離だけを使う。

追加ユースケースは、12 px程度ずれた上スライドでも直進を保つこと、大きく横へ滑らせた後に短い戻しで旋回を止められること、北側の道を入江経由で一周して元の浜へ戻れること。単体検査に加えて、実タッチイベントと実際の配置物を使った歩行検証で確認する。
